# Docker Support — RAG Platform API

A Retrieval-Augmented Generation platform, built with NestJS, TypeScript, and pnpm, that answers Docker documentation questions grounded in the real Docker docs. The first knowledge domain is Docker Official Documentation; see [`docs/architecture/rag-platform-architecture.md`](./docs/architecture/rag-platform-architecture.md) for the full platform architecture.

The pipeline is a sequence of CLI stages (ingest → chunk → embed → index) that populate a Qdrant vector store from a ZIP of Markdown docs, plus a live HTTP endpoint (`POST /query`) that retrieves relevant chunks and generates a cited, grounded answer via Google Gemini (LangChain). Retrieval never calls the LLM when there isn't enough grounded context, and every answer's citations are validated against the chunks actually retrieved — never fabricated.

## Setup

```bash
cp .env.example .env
pnpm install
docker compose up -d   # starts local Qdrant (see docker-compose.yml)
pnpm run start:dev
```

The app starts on the port configured in `.env` (default `3000`). `POST /query` requires a populated Qdrant collection — run the full pipeline first (`ingest` → `chunk` → `embed` → `index`, see [Scripts](#scripts) below) unless `VECTOR_STORE_PROVIDER=fake`.

## Health endpoints

- `GET /health/live` — process-level liveness (memory heap/RSS checks). Use for a Kubernetes liveness probe.
- `GET /health/ready` — readiness (same checks today; the attachment point for future database/cache/vector-store readiness indicators). Use for a Kubernetes readiness probe.

Both return `200` with `{"status": "ok", ...}` when healthy, or `503` when any underlying check fails.

## Query endpoint

`POST /query` — retrieves relevant Docker documentation chunks from Qdrant and generates a grounded, cited answer via Gemini.

**Request:**

```json
{ "text": "What is a Docker container?" }
```

**Response:**

```json
{
  "answer": "A Docker container is a sandboxed process running on a host machine... [S1]",
  "sources": [
    {
      "documentId": "...",
      "chunkId": "...",
      "title": "What is Docker?",
      "headingPath": "Docker architecture › Docker objects › Containers",
      "source": "docs-main/content/get-started/docker-overview.md",
      "score": 0.87
    }
  ],
  "metadata": {
    "provider": "google",
    "framework": "langchain",
    "model": "gemini-3.6-flash",
    "retrievedCount": 10,
    "usage": { "inputTokens": 970, "outputTokens": 218, "totalTokens": 1188 },
    "costUsd": 0.001545
  }
}
```

- `sources` only includes chunks Gemini actually cited (`[S1]`-style markers, validated against real retrieved chunks) — never fabricated, and empty when the model correctly declines to answer.
- If retrieval finds no relevant context, the LLM is never called — `answer` is a fixed "not enough information" message with empty `sources`, at no API cost.
- `usage`/`costUsd` are omitted (not zeroed) when the provider doesn't report usage data.

**Error responses:**

| Status | Cause                                                                                                                                         |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `400`  | Missing/empty/oversized `text`, or the estimated prompt exceeds `LLM_MAX_PROMPT_TOKENS`                                                       |
| `503`  | The target Qdrant collection's embedding config doesn't match the configured `EMBEDDING_*` settings, or the LLM provider failed after retries |

## Git hooks

This repo uses [Husky](https://typicode.github.io/husky/) for git hooks, installed automatically via the `prepare` script on `pnpm install`:

- **pre-commit** — runs `lint-staged` (ESLint + Prettier) on staged files.
- **commit-msg** — runs [commitlint](https://commitlint.js.org/) against [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `chore:`, `docs:`, etc.). Non-conforming commit messages are rejected.
